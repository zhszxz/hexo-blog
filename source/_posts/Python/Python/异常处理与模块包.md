# 一、异常处理

异常是程序运行时的错误。Python 用「抛异常 → 捕获处理」的机制，让代码在出错时能优雅降级，而不是直接崩溃。

### 1.1 常见异常与继承体系

Python 的所有异常都继承自 `BaseException`，日常处理的是它的子类 `Exception`。常见内置异常：

| 异常 | 触发场景 |
| ---- | -------- |
| `NameError` | 使用未定义的变量/函数名 |
| `TypeError` | 类型不匹配（如 `"1" + 1`） |
| `ValueError` | 类型对但值不对（如 `int("abc")`） |
| `IndexError` | 索引越界 |
| `KeyError` | 字典 key 不存在 |
| `ZeroDivisionError` | 除以 0 |
| `AttributeError` | 访问对象不存在的属性/方法 |
| `FileNotFoundError` | 文件不存在 |
| `ImportError` / `ModuleNotFoundError` | 导入失败 |
| `StopIteration` | 迭代器取完 |

继承关系（部分）：`BaseException → Exception → ...`，其中 `ValueError`、`TypeError` 等继承自 `Exception`，`KeyboardInterrupt`、`SystemExit` 直接继承 `BaseException`（所以 `except Exception` 不会捕获 Ctrl+C 的中断，这是刻意设计）。

### 1.2 try / except / finally

基本结构（摘自练习代码 `chapter02/22.异常.py`）：

```python
try:
    print("ABC".hello)          # 会抛 AttributeError
except AttributeError as e:
    print(f"出错了: {e}")
finally:
    print("资源释放 ~")          # 无论是否异常都执行
```

`try` 中一旦某行抛异常，**后续代码不再执行**，直接跳到对应的 `except`。

### 1.3 捕获多个异常

```python
try:
    # 可能抛多种异常的代码
    x = int(input("输入数字:"))
    result = 10 / x
except ValueError as e:
    print("输入的不是数字:", e)
except ZeroDivisionError as e:
    print("不能除以 0:", e)
except Exception as e:      # 兜底：捕获所有异常
    print("其他错误:", e)
```

要点：

- 多个 `except` **从上到下依次匹配，命中一个就停止**，所以具体的异常放前面，`Exception` 兜底放最后。
- 一个 `except` 捕获多个类型：`except (ValueError, TypeError) as e:`。
- `except:` 不写类型 = `except Exception:`，会捕获所有（但不推荐，会掩盖 bug）。

### 1.4 else 子句

`else` 在 **try 块没有抛异常时**执行（与循环的 else 语义类似）：

```python
try:
    result = 10 / 2
except ZeroDivisionError:
    print("出错了")
else:
    print(f"成功，结果是 {result}")   # 只有没异常才执行
```

### 1.5 raise 主动抛出异常

```python
def check_age(age):
    if age < 0:
        raise ValueError("年龄不能为负数")   # 主动抛异常
    return age

try:
    check_age(-1)
except ValueError as e:
    print(e)     # 年龄不能为负数
```

### 1.6 raise from 异常链

处理异常时想「包装」成另一个异常、同时保留原始异常信息，用 `raise ... from ...`：

```python
try:
    x = int("abc")
except ValueError as e:
    raise RuntimeError("转换失败") from e   # 保留原异常链
```

用 `from None` 可以刻意截断异常链（隐藏底层实现细节）。

### 1.7 自定义异常

继承 `Exception`（或其子类）定义业务异常：

```python
class BusinessError(Exception):
    """业务异常"""
    def __init__(self, message, code=500):
        super().__init__(message)
        self.code = code

def transfer(money):
    if money <= 0:
        raise BusinessError("金额必须大于 0", code=400)

try:
    transfer(-100)
except BusinessError as e:
    print(f"错误码 {e.code}: {e}")
```

企业项目通常定义一套业务异常体系，便于统一捕获、统一返回错误码。

### 1.8 assert 断言

`assert 条件, 消息`：条件为假时抛 `AssertionError`，用于开发期自检和调试：

```python
def divide(a, b):
    assert b != 0, "除数不能为 0"
    return a / b
```

> `assert` 可被 `python -O`（优化模式）关闭，所以**不要用它做正式参数校验**，只用于调试和测试。

### 1.9 异常的传递

函数内未捕获的异常会**逐层向上抛**，直到被某个调用方捕获，或到达顶层导致程序崩溃（摘自练习代码）：

```python
def fun1():
    fun2()

def fun2():
    print(my_color)        # NameError

try:
    fun1()                 # 异常从 fun2 → fun1 → 这里被捕获
except Exception as e:
    print("捕获到异常:", e)
```

# 二、模块

模块就是一个 `.py` 文件，是 Python 组织代码的基本单位。把功能相近的代码放进模块，供其他文件导入复用。

### 2.1 导入方式

```python
# 方式一：import 模块名，用 模块名.功能 调用
import random
print(random.randint(1, 100))

# 方式二：import 模块 as 别名
import random as rd
print(rd.randint(1, 100))

# 方式三：from 模块 import 功能，直接用功能名
from random import randint
print(randint(1, 100))

# 方式四：from 模块 import 功能 as 别名
from random import randint as rint

# 方式五：from 模块 import *（导入全部，不推荐）
from random import *
```

推荐用前两种（带命名空间，来源清晰），避免 `import *` 造成名字污染。

### 2.2 `__name__ == "__main__"`

`__name__` 是内置变量，表示当前模块名（摘自练习代码 `module02/my_fun.py`）：

- **直接运行**该文件时，`__name__` 的值是 `"__main__"`。
- 该文件被**导入**时，`__name__` 的值是模块名（如 `"my_fun"`）。

```python
# 写在模块末尾，用于模块的自我测试
if __name__ == '__main__':
    log_separator1()      # 只有直接运行本文件才执行；被导入时不执行
```

这是 Python 模块的标准写法，既能让文件单独运行测试，又不会在导入时误执行测试代码。

### 2.3 `__all__` 控制导出

`from 模块 import *` 时，用 `__all__` 指定导出哪些名字：

```python
__all__ = ["log_separator1", "log_separator3", "PI"]
```

不写 `__all__` 时，`import *` 会导入所有「不以单下划线开头」的公开名字。`__all__` 只在 `import *` 时生效，用 `import 模块` 或 `from 模块 import 具体名` 不受影响。

### 2.4 模块搜索路径 sys.path

`import` 时 Python 按 **`sys.path`** 里的顺序查找模块：当前目录 → 环境变量 `PYTHONPATH` → 标准库目录 → 第三方包目录（site-packages）。

```python
import sys
print(sys.path)          # 查看搜索路径
sys.path.append("/path/to/module")   # 临时追加路径（不推荐，正式项目用包管理）
```

导入失败通常是因为模块不在 `sys.path` 能找到的位置。

# 三、包（Package）

包是**含有 `__init__.py` 的文件夹**，用于组织多个模块，形成命名空间（如 `utils.my_fun`）。

### 3.1 包的结构与导入

```
utils/                  # 包
├── __init__.py         # 包的标志文件（可为空，也可写初始化代码）
├── my_fun.py
└── my_var.py
```

```python
# 导入包中的模块
import utils.my_fun
utils.my_fun.log_separator1()

from utils import my_fun
my_fun.log_separator1()

# 导入模块中的具体功能
from utils.my_fun import log_separator1, log_separator3
log_separator1()
```

### 3.2 `__init__.py` 的作用

`__init__.py` 在包被导入时自动执行，常用于（摘自练习代码 `utils/__init__.py`）：

```python
__version__ = "1.0.0"      # 包元信息
__author__ = "zhangsan"

__all__ = ["my_fun", "my_var"]   # 控制 from 包 import * 导入哪些模块
```

`from utils import *` 时，会按 `__all__` 导入 `my_fun`、`my_var`。

> 注：Python 3.3+ 引入了「命名空间包」，没有 `__init__.py` 的文件夹也能被当作包导入，但**规范做法仍是保留 `__init__.py`**，语义更清晰、兼容性更好。

### 3.3 相对导入

包内部模块之间互相引用，用**相对导入**（以 `.` 开头）：

```python
# 假设包结构：pkg/a.py 里要导入同包的 b
from . import b          # 当前包下的 b
from .b import func      # 当前包下 b 模块的 func
from .. import other     # 上一级包的 other
```

相对导入只能用在**包内部的模块**里，直接运行的脚本（`__main__`）不能用相对导入。

# 四、虚拟环境与包管理

第 1 篇 1.3 节已详细讲过，这里只列要点：

- 每个项目独立虚拟环境：`python -m venv .venv`，激活后 `pip` 装包互不干扰。
- 依赖锁定：`pip freeze > requirements.txt`，团队按 `pip install -r requirements.txt` 同步。
- 更现代方案：`poetry` / `uv`（管理依赖 + 发布 + 虚拟环境一体）。

# 小结

本篇两个主题：

1. **异常处理**：异常继承体系、`try/except/else/finally`、多 except 从上到下匹配、`raise` 与 `raise from`、自定义异常、`assert` 只用于调试、异常逐层向上传递。企业开发中「自定义异常 + 统一捕获」是标准做法。
2. **模块与包**：`import` 的多种形式、`__name__ == "__main__"`、`__all__`、`sys.path` 搜索顺序、包与 `__init__.py`、相对导入。它们是理解 Python 项目结构（尤其是大型项目分层）的基础。
