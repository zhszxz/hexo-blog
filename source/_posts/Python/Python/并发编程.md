并发编程是 Python 进阶的最高峰，也是面试必考。本篇系统讲清 **GIL、多线程、多进程、协程** 四者及选型，帮助你面对「这个场景用线程还是协程」时不再犹豫。

# 一、并发基础与 GIL

### 1.1 三个概念

- **进程（Process）**：操作系统资源分配的基本单位，每个进程有独立的内存空间。Python 用 `multiprocessing` 创建。
- **线程（Thread）**：进程内的执行单元，同一进程内线程共享内存。Python 用 `threading` 创建。
- **协程（Coroutine）**：用户态的轻量级「微线程」，在单线程内通过事件循环调度切换，用 `asyncio` 实现。

一句话：**进程是资源容器，线程是执行单元，协程是用户态的任务调度**。

### 1.2 GIL 是什么

GIL（Global Interpreter Lock，全局解释器锁）是 **CPython 解释器**的一个互斥锁：**同一时刻，只有一个线程能执行 Python 字节码**。

几个关键认识（摘自练习代码 `chapter02/39.GIL.py`）：

- GIL **不是 Python 语言的特性，而是 CPython 解释器的实现细节**（Jython、IronPython 没有 GIL）。
- GIL 的存在是为了保护解释器内部（尤其是**引用计数**）的线程安全，让 C 扩展更易编写。
- 线程执行 Python 代码前必须获取 GIL，执行一段时间片后释放，或在** I/O 操作时释放**。

### 1.3 GIL 的影响（最重要）

| 任务类型 | 多线程效果 | 原因 |
| -------- | ---------- | ---- |
| **CPU 密集型**（计算、循环） | ❌ 无法真正并行，甚至更慢 | 线程抢 GIL，实际串行执行 |
| **I/O 密集型**（网络、文件、数据库） | ✅ 有效 | I/O 等待时释放 GIL，其他线程可执行 |

```python
# CPU 密集：多线程不如多进程（GIL 限制）
# I/O 密集：多线程和多进程效果相近（I/O 时释放 GIL）
```

这也是为什么 Python 的「多线程」常被吐槽——对纯计算任务，多线程并不能利用多核。

### 1.4 突破 GIL 的方法

1. **CPU 密集 → 多进程**：`multiprocessing`，每个进程有独立解释器和 GIL，真正并行。
2. **I/O 密集 → 协程/多线程**：`asyncio` 或 `threading`，等待 I/O 时切换。
3. **把计算下沉到 C 扩展**：如 `numpy`，在 C 层释放 GIL 做并行。
4. **换实现**：Jython、IronPython，或 Python 3.13+ 的**无 GIL 实验性选项**（`python3.13t`，尚未全面稳定）。

### 1.5 选型速查（先记结论，后面详解）

| 场景 | 推荐方案 |
| ---- | -------- |
| CPU 密集（计算量大） | 多进程 `multiprocessing` / `ProcessPoolExecutor` |
| I/O 密集（大量网络请求） | 协程 `asyncio`（首选）或线程池 |
| 简单并发任务 | `ThreadPoolExecutor` / `ProcessPoolExecutor` |
| 混合场景 | 按任务类型拆分，分别处理 |

# 二、多线程 threading

线程共享进程内存，创建开销小，适合 I/O 密集任务。

### 2.1 创建线程

方式一：`Thread(target=函数, args=参数)`（摘自练习代码 `chapter02/37.多线程.py`）：

```python
from threading import Thread
import time

def coding():
    for i in range(5):
        print(f"敲代码 {i}")
        time.sleep(0.5)

t = Thread(target=coding)   # 创建线程对象
t.start()                   # 启动线程
t.join()                    # 等待线程执行完毕
```

方式二：继承 `Thread` 类，重写 `run()`：

```python
class CodingThread(Thread):
    def run(self):
        for i in range(5):
            print(f"敲代码 {i}")
            time.sleep(0.5)

t = CodingThread()
t.start()
t.join()
```

关键方法：

- `start()`：启动线程（内部调用 `run()`）。
- `join()`：阻塞主线程，等待该线程结束。
- `daemon=True`：设为守护线程，主线程结束时自动终止。

### 2.2 线程安全与锁

多个线程共享变量，同时读写会产生**竞态条件**（结果不确定）。用锁保证同一时刻只有一个线程访问临界区：

```python
from threading import Thread, Lock

lock = Lock()
count = 0

def add():
    global count
    for _ in range(100000):
        with lock:          # 加锁，with 退出自动释放
            count += 1

threads = [Thread(target=add) for _ in range(4)]
for t in threads: t.start()
for t in threads: t.join()
print(count)                # 400000，不加锁会得到错误结果
```

锁的两种用法（摘自练习代码 `30.多进程.py`）：

```python
# 方式一：手动 acquire / release（异常时可能漏释放）
lock.acquire()
# 临界区
lock.release()

# 方式二：with（推荐，自动获取和释放，即使异常也释放）
with lock:
    # 临界区
```

### 2.3 常用同步原语

| 原语 | 作用 |
| ---- | ---- |
| `Lock` | 互斥锁（不可重入） |
| `RLock` | 可重入锁（同一线程可多次加锁，加几次释放几次） |
| `Event` | 事件：线程间发信号（`set`/`wait`/`clear`） |
| `Condition` | 条件变量：`wait`/`notify` 实现生产者消费者 |
| `Semaphore` | 信号量：限制同时访问的线程数 |

```python
from threading import RLock, Event, Semaphore

# RLock：可重入，同一线程可重复加锁
rlock = RLock()
with rlock:
    with rlock:      # 重入，不会死锁
        pass

# Event：一个线程等另一个线程的信号
event = Event()
# 线程 A：等待信号
event.wait()
# 线程 B：发信号
event.set()

# Semaphore：最多 3 个线程同时进入
sem = Semaphore(3)
with sem:
    pass
```

> 死锁：两个线程各自持锁又互相等对方的锁。用 `with` 加锁、避免嵌套锁、`RLock` 防重入，可降低死锁风险。

# 三、多进程 multiprocessing

多进程**内存不共享**，每个进程有独立解释器，能绕过 GIL 真正利用多核，适合 CPU 密集任务。

### 3.1 创建进程

方式一：`Process(target=函数, args=参数)`（摘自练习代码 `chapter02/30.多进程.py`）：

```python
from multiprocessing import Process
import os, time

def coding(name, count):
    print(f"子进程 pid={os.getpid()}, 父进程 ppid={os.getppid()}")
    for i in range(count):
        print(f"{name} 敲代码 {i}")
        time.sleep(0.1)

if __name__ == '__main__':          # 多进程必须写在 main 保护里！
    p = Process(target=coding, args=("小明", 10))
    p.start()
    p.join()
```

方式二：继承 `Process` 类，重写 `run()`（摘自练习代码 `35.继承Process类实现多进程.py`）：

```python
class CodingProcess(Process):
    def __init__(self, name):
        super().__init__()
        self.name = name
    def run(self):
        for i in range(10):
            print(f"{self.name} 敲代码 {i}")

p = CodingProcess("小明")
p.start()
p.join()
```

> **重要**：多进程代码必须放在 `if __name__ == '__main__':` 里（Windows 下尤其必要），否则子进程会递归创建进程导致报错。

### 3.2 进程不共享变量

进程内存独立，**子进程修改变量不影响主进程**（摘自练习代码 `32.进程不共享变量.py`）：

```python
num = 100

def task():
    global num
    num += 10          # 修改的是子进程自己的 num 副本

p = Process(target=task)
p.start()
p.join()
print(num)             # 100，主进程的 num 没变
```

这与多线程（共享内存）完全不同——线程共享变量需要加锁，进程则天生隔离，需要显式通信。

### 3.3 守护进程

`daemon=True` 的进程是守护进程：**主进程结束时自动终止**，不能创建子进程，退出不执行清理（摘自练习代码 `31.守护进程.py`）：

```python
p = Process(target=monitor, daemon=True)
p.start()
# 主进程结束时，守护进程 p 自动结束
```

### 3.4 进程间通信：Queue 与 Pipe

进程不共享内存，用 `Queue` 或 `Pipe` 通信。

**Queue**（生产者-消费者模式，摘自练习代码 `34.进程通信.py`）：

```python
from multiprocessing import Process, Queue

def producer(q):
    for i in range(5):
        q.put(i)              # 放入数据
        print(f"生产 {i}")

def consumer(q):
    for i in range(5):
        print(f"消费 {q.get()}")   # 取出数据

q = Queue()                    # 不传 size 或传 0 表示不限制
p1 = Process(target=producer, args=(q,))
p2 = Process(target=consumer, args=(q,))
p1.start(); p2.start()
p1.join(); p2.join()
```

Queue 方法：`put`（放入，可 `timeout`）、`get`（取出）、`put_nowait`、`full()`、`empty()`、`qsize()`。

**Pipe**（点对点通信，摘自练习代码 `34.进程通信.py`）：

```python
from multiprocessing import Pipe

conn1, conn2 = Pipe()     # 返回管道的两端
# 一端 send，另一端 recv
conn1.send("你好")
print(conn2.recv())       # 你好
```

### 3.5 进程池 Pool

重复创建进程开销大，进程池复用固定数量的进程（摘自练习代码 `36.进程池.py`，用的是更现代的 `concurrent.futures`，见下一节）。

传统 `multiprocessing.Pool` 的写法（了解即可）：

```python
from multiprocessing import Pool

def square(n):
    return n * n

with Pool(4) as pool:          # 4 个进程
    results = pool.map(square, range(10))
    print(results)
```

# 四、concurrent.futures 线程池/进程池（推荐）

`concurrent.futures` 提供了统一的线程池/进程池接口，**比手动创建线程/进程更简单、更安全**，是企业开发首选。

### 4.1 ThreadPoolExecutor / ProcessPoolExecutor

```python
from concurrent.futures import ThreadPoolExecutor, ProcessPoolExecutor
import time

def work(n):
    time.sleep(1)
    return f"任务 {n} 完成"

# I/O 密集用线程池
with ThreadPoolExecutor(3) as pool:     # 最多 3 个线程
    results = pool.map(work, range(6))  # map 批量提交，按提交顺序返回结果
    print(list(results))

# CPU 密集用进程池
with ProcessPoolExecutor(3) as pool:
    results = pool.map(work, range(6))
    print(list(results))
```

- `with` 自动关闭池（等价 `shutdown(wait=True)`，会等任务执行完）。
- `executor.map(fn, iterable)`：批量提交，**结果顺序与提交顺序一致**。

### 4.2 submit 与 as_completed

`submit` 逐个提交，返回 `Future` 对象；`as_completed` 按**完成顺序**获取结果（摘自练习代码 `36.进程池.py`）：

```python
from concurrent.futures import ProcessPoolExecutor, as_completed

with ProcessPoolExecutor(3) as executor:
    futures = [executor.submit(work, i) for i in range(1, 8)]
    for future in as_completed(futures):   # 谁先完成谁先返回
        print(future.result())             # 获取结果（会阻塞直到完成）
```

- `submit(fn, *args)`：提交单个任务，返回 Future。
- `future.result()`：阻塞等待并返回结果。
- `as_completed(futures)`：迭代已完成的 Future，**顺序 = 完成顺序**（适合「先完成先处理」的场景）。
- `future.add_done_callback(cb)`：任务完成后自动调用回调（摘自练习代码）。

```python
def callback(future):
    print(future.result())

future = executor.submit(work, 1)
future.add_done_callback(callback)
```

### 4.3 map vs submit 怎么选

| 方式 | 特点 | 适用 |
| ---- | ---- | ---- |
| `map` | 简单，结果按提交顺序 | 批量同构任务，不关心完成顺序 |
| `submit + as_completed` | 灵活，按完成顺序取结果 | 任务耗时差异大，想「先完成先处理」 |

# 五、协程 asyncio

协程是 Python 处理**大量 I/O 并发**的最优方案：在单线程内用事件循环调度，一个线程就能扛住成千上万的并发连接，且没有线程切换开销。

### 5.1 协程函数与协程对象

- **协程函数**：用 `async def` 定义的函数。
- **协程对象**：调用协程函数返回的对象，**不会立即执行**（摘自练习代码 `40.协程函数与协程对象.py`）。

```python
import asyncio

async def work():
    print("Start")
    return "done"

coro = work()                # 得到协程对象，尚未执行
print(coro)                  # <coroutine object work at ...>

result = asyncio.run(coro)   # 真正执行
print(result)                # done
```

### 5.2 asyncio.run 与事件循环

`asyncio.run(coro)` 做了三件事（摘自练习代码）：

1. 创建**事件循环**（Event Loop）；
2. 把协程包装成 Task 交给事件循环；
3. 启动事件循环，**阻塞直到任务结束**并返回结果。

它是运行协程的**唯一入口**，每个程序通常只在主入口调用一次。

### 5.3 await 的作用

`await` 后面只能跟**可等待对象**（协程、Task、Future）。它的行为是「挂起 → 等待 → 恢复」（摘自练习代码 `41.await.py`）：

```python
async def work():
    print("Start")
    await asyncio.sleep(2)    # 挂起 2 秒，期间让出控制权
    print("End")

asyncio.run(work())
```

关键区别（摘自练习代码的注释）：

- `await` 后遇到 **I/O 操作**（网络请求、`asyncio.sleep` 等）→ 控制权交回事件循环，调度其他任务。
- `await` 后是**纯计算**（`print`、数学运算）→ 不会发生切换，仍是顺序执行。

> **必须用 `asyncio.sleep` 而不是 `time.sleep`**：`time.sleep` 是阻塞的，会卡死整个事件循环；`asyncio.sleep` 是异步的，等待期间让出控制权。

### 5.4 并发执行多任务：create_task 与 gather

**同步执行**（顺序 await，白白浪费等待时间，摘自练习代码 `42.协程同步执行多任务.py`）：

```python
async def work(n, delay):
    await asyncio.sleep(delay)
    return f"work{n}"

async def main():
    r1 = await work(1, 2)   # 等 2 秒
    r2 = await work(2, 2)   # 再等 2 秒
    r3 = await work(3, 2)   # 再等 2 秒，总共 6 秒
    print(r1, r2, r3)

asyncio.run(main())
```

**异步执行**（用 `create_task` 并发，总共只要 2 秒，摘自练习代码 `43.协程异步执行多任务.py`）：

```python
async def main():
    task1 = asyncio.create_task(work(1, 2))   # 包装成 Task，立即调度
    task2 = asyncio.create_task(work(2, 2))
    task3 = asyncio.create_task(work(3, 2))

    r1 = await task1      # 等待时，其他 task 也在执行
    r2 = await task2
    r3 = await task3
    print(r1, r2, r3)

asyncio.run(main())
```

**`asyncio.gather`**：批量并发执行多个协程，一次性收集所有结果（更简洁，摘自练习代码 `45.图片下载_协程方式.py`）：

```python
async def main():
    coros = [work(1, 2), work(2, 2), work(3, 2)]
    results = await asyncio.gather(*coros)   # 并发执行，返回结果列表
    print(results)                           # ['work1', 'work2', 'work3']

asyncio.run(main())
```

`create_task` 与 `gather` 的选择：

- `create_task`：需要精细控制每个任务（逐个 await、取消、回调）。
- `gather`：批量并发、一次性收集结果，更简单。

### 5.5 实战对比：传统 vs 协程下载图片

传统同步方式（串行下载，摘自练习代码 `44.图片下载_传统方式.py`）：

```python
import time, requests

def download_picture(url):
    response = requests.get(url)
    with open(f"{int(time.time()*1000)}.jpg", "wb") as f:
        f.write(response.content)

start = time.time()
for url in url_list:
    download_picture(url)        # 一个一个下，总耗时 = 各图耗时之和
print(f"耗时 {time.time() - start:.2f} 秒")
```

协程异步方式（并发下载，摘自练习代码 `45.图片下载_协程方式.py`）：

```python
import asyncio, aiohttp

async def download_picture(session, url):
    async with session.get(url) as response:
        content = await response.read()
        with open(f"{int(time.time()*1000)}.jpg", "wb") as f:
            f.write(content)

async def main():
    async with aiohttp.ClientSession() as session:
        coros = [download_picture(session, url) for url in url_list]
        await asyncio.gather(*coros)   # 并发下载，总耗时约 = 最慢一张

asyncio.run(main())
```

要点：异步代码需要配套的**异步库**（`aiohttp` 代替 `requests`、异步驱动代替同步 DB 驱动），否则阻塞调用会卡死事件循环。

### 5.6 协程同步原语

`asyncio` 也有锁、事件等，用于协程间的同步（在多线程里是 `threading.Lock`，协程里是 `asyncio.Lock`）：

```python
import asyncio

async def main():
    lock = asyncio.Lock()
    async with lock:            # 异步锁
        pass
```

# 六、三种并发方式对比与选型总结

| 维度 | 多线程 | 多进程 | 协程 |
| ---- | ------ | ------ | ---- |
| 创建开销 | 小 | 大 | 极小 |
| 内存共享 | 共享（需锁） | 不共享（需通信） | 共享（单线程） |
| 适用任务 | I/O 密集 | CPU 密集 | 大量 I/O 并发 |
| GIL 影响 | 受 GIL 限制 | 绕过 GIL | 单线程，无 GIL 问题 |
| 并发能力 | 几十~几百 | 受 CPU 核数限制 | 成千上万 |
| 学习难度 | 中 | 中 | 高 |

**最终选型口诀：**

1. **CPU 密集**（大量计算）→ **多进程** / `ProcessPoolExecutor`。
2. **I/O 密集**（网络请求、文件、数据库）→ **协程 `asyncio`**（并发量大时最优）或 **线程池**。
3. **简单并发、任务量不大** → `ThreadPoolExecutor` / `ProcessPoolExecutor` 最省事。
4. 需要**充分利用多核做计算**，又不想用进程 → 用 `numpy` 等 C 扩展（内部释放 GIL）。

# 小结

并发编程是 Python 面试和架构设计的重点，核心结论：

1. **GIL**：CPython 的全局锁，导致 CPU 密集多线程无法并行，但 I/O 密集有效；破解靠多进程/协程/C 扩展。
2. **多线程**：`Thread` + `start/join/daemon`，共享内存需 `Lock/RLock` 同步，适合 I/O 密集。
3. **多进程**：`Process` + `Queue/Pipe` 通信，内存隔离，绕过 GIL，适合 CPU 密集。
4. **线程池/进程池**：`concurrent.futures` 的 `map` / `submit + as_completed`，是日常首选。
5. **协程**：`async/await` + 事件循环，`create_task`/`gather` 并发，配合 `aiohttp` 等异步库，是海量 I/O 并发的利器。
